# SQL 체험형 학습 검토

검토일: 2026-11-09

## 후속 구현

같은 날 사용자 요청으로 SQL 네 장면을 `sql_experience.gd`의 카드 운반 방식으로 연결했다. 조회는 원본 복사본 분류와 열 렌즈, 집계는 거래 바구니와 보고서 배달, JOIN은 직원 명찰의 실제 키 연결, 서브쿼리는 자료 수집·계산·토큰 전달·학생 분류를 수행한다. 정답 화살표와 쿼리 문구 선택 장치는 플레이 화면에서 제거했다. 제출 후 결과·SQL 해설을 확인하기 전에는 다음 문제로 진행하지 않는다. SQL 계산기는 기존 구현을 재사용한다.

실제 장면의 상호작용 지점으로 19개 의뢰를 해결하고, 잘못 배달한 카드 거부·운반 상태 되돌리기·초기화·접근성을 검사했다. 전용 검사 643개, 기존 계산·메뉴 검사 287개, 다른 실습 이동 검사 209개가 실패 없이 통과했다. 실행 화면도 별도로 렌더링해 확인했다. 초보자 대상 사용성 검증은 별도로 필요하다.

아래 내용은 이 수정 이전의 문제 진단과 설계 기준을 기록한 것이다.

## 판단

현재 SQL 실습은 실제 결과를 계산하는 질의 조립형 학습이다. 정적인 객관식 문항만 있는 것은 아니지만, 자료구조처럼 대상을 직접 다루며 원리를 경험한다는 초기 의도에는 충분히 도달하지 못했다. 로봇이 움직이는 것과 SQL 연산을 체험하는 것은 별개다.

앞선 기획도 블록 선택과 질의 조립을 기본 방식으로 명시했다. 따라서 구현자만의 문제가 아니라 기획에서 체험 동작과 결과 관찰을 구체화하지 못한 부분도 있다. 기존 계산 로직과 배경은 재사용할 수 있다.

## 검토 범위와 방법

- 대상: SQL01_Query, SQL02_GroupBy, SQL03_Join, SQL04_Subquery의 각 3레벨, 총 12레벨.
- 실제 Godot 실행에서 시작·완료·대표 오답 결과 화면을 저장하고, SQL 계산·상호작용·안내 코드를 대조했다.
- 창 제어 도중 잘못된 캡처와 창 소실이 있어 수동 플레이 완주는 하지 않았다. 이후 앱 내부 검토 스크립트로 장면을 실행하고 상태를 검증했다.
- 안내만 따른 경로의 검증은 각 상태에서 `next_action()`이 반환하는 장치에 실제 상호작용 함수를 호출하는 방식이다. 자연스러운 이동 조작성이나 초보자 이해도를 검증한 것으로 해석하면 안 된다.
- 진행 저장과 네트워크 자동 전송을 끈 검토 실행을 사용했다. 제품 코드와 맵 배치 좌표는 변경하지 않았다.
- 근거 화면: `tmp/sql_review/`. 실행 기록: `.godot/sql_review_capture.log`.

## 확인 결과

| 항목 | 결과 | 의미 |
|---|---|---|
| 자연어 의뢰 | 의뢰·현재 단계·목표 열과 행 수 표시 | 이전보다 해야 할 일은 명확해졌다 |
| 실제 계산 | WHERE 적용, 집계, JOIN 조합, 내부 질의 값을 실제 계산 | 단순 고정 정답 화면은 아니다 |
| 선택 방식 | 대부분 E를 눌러 정해진 조건·연산자를 순환 선택 | 데이터 대상보다 설정 문구를 조작한다 |
| 화살표 | 현재 설정과 목표 설정을 비교해 다음 수정 장치를 지시 | 이해 없이 화살표 변화만 관찰해도 정답 설정에 도달한다 |
| JOIN 기본값 | 첫 레벨의 키와 INNER가 이미 정답 | 연결 판단 없이 실행 한 번으로 완료한다 |
| 결과 관찰 | 회색 제외 행, 결과표, JOIN 선, 집계 단계별 개수, 내부 값 표시 | 체험형으로 발전시킬 기반은 존재한다 |
| 부분 문제 완료 | 다음 문제로 곧바로 전환하며 상태 재설정 | 맞힌 이유와 전후 차이를 충분히 관찰할 틈이 부족하다 |

안내 경로만 호출한 검증에서 12레벨 모두 실수 0으로 완료했다. 특히 SQL03 레벨 1은 실행 1회, 레벨 2는 종류 변경과 실행 2회, SQL04 레벨 1은 내부 실행과 외부 실행 2회로 완료했다. 이 결과는 학습을 입증하지 않으며, 정답 안내 의존성을 보여주는 근거다.

대표 오답 실행에서도 실제 결과가 변함을 확인했다. SQL01은 60점 이상 4행, SQL02는 부서별 평균, SQL03은 INNER의 2행, SQL04는 평균 80 이상인 2행이 실제로 표시됐다.

## 우선 보완할 문제

1. **화살표가 정답을 판별한다.** `next_query_key`, `next_group_key`, `next_join_key`, `next_sub_key`가 목표 설정과 현재 상태를 비교한다. 특히 조건 장치의 화살표가 다른 장치로 넘어가는 순간이 정답 신호가 된다. 일반 모드에서는 작업 단계·위치만 안내하고, 구체적 정답 경로는 명시적으로 요청한 최종 힌트로 제한한다.
2. **초기 설정만으로 문제가 풀린다.** JOIN의 연결 키와 종류, 서브쿼리의 AVG와 비교 연산자가 이미 맞춰져 있다. 초기에는 '미설정' 상태를 두고 학습자가 개념 판단을 한 번 이상 하게 한다. 첫 입문은 예시로 허용하되 연습과 구분한다.
3. **세계 속 행동이 연산의 의미와 약하게 연결된다.** 열 이름·조건 문구를 고르는 행동에서 끝나지 않고, 선택한 연산에 따라 실제 레코드·그룹·연결·중간 결과가 움직이도록 한다.
4. **결과 관찰과 설명이 부족하다.** 실행 후 원본 → 중간 상태 → 결과를 멈춰 관찰하고, 왜 특정 행이 남거나 사라졌는지 확인한 뒤 다음 문제로 이동한다.
5. **장식과 실제 상태를 구분해야 한다.** JOIN 배경에는 실행 전부터 연결선과 결과 카드가 그려져 있다. 실제 표는 왼쪽 dept_id 10,20과 오른쪽 id 20,10 순서인데 장식 선은 가로로 이어져 있어 잘못된 대응처럼 보인다. 의미가 있는 선·숫자·카드는 배경에서 가리고 런타임 데이터로만 표시한다.

## 권장 공통 플레이 흐름

NPC의 상황 의뢰 → 원본 레코드 관찰 → 연산 장치 설정 → 결과 예측 → 실행과 데이터 변화 관찰 → 결과·근거 확인 → SQL과 행동 대응 해설 → 다음 문제.

SQL은 선언형이므로 모든 행을 일일이 운반하는 수작업으로 바꿀 필요는 없다. 장치를 설정하면 전체 데이터가 같은 규칙으로 처리되는 모습을 보여주는 것이 핵심이다. 직접 SQL 입력을 추가하는 것만으로 체험 부족이 해결되지는 않는다.

## 게임별 체험 동작 제안

| 게임 | 상황 목표 | 직접 하는 일 | 관찰할 결과 |
|---|---|---|---|
| SQL01 조회 | 장학생 안내에 필요한 이름·부서만 추출 | 열 렌즈를 출력판에 꽂고 점수 필터 게이트 설정 | 조건에 맞는 행이 통과하고 선택 열만 결과 카드에 복사됨 |
| SQL02 집계 | 부서별 실적판 완성 | 그룹 기준 태그와 집계 장치를 배치 | 행이 부서 바구니로 모이고 COUNT·SUM·AVG가 계산됨. WHERE는 모으기 전, HAVING은 모은 뒤 적용 |
| SQL03 JOIN | 직원에게 올바른 부서 명찰 지급 | 양쪽 표의 키 소켓을 연결하고 미매칭 처리 모드 결정 | 10은 10, 20은 20과 연결됨. LEFT에서 짝 없는 직원이 NULL 명찰로 남고 1:N이면 결과가 늘어남 |
| SQL04 서브쿼리 | 평균 초과 대상자 선발 | 내부 계산 장치로 평균 토큰을 만들고 외부 게이트에 연결 | 평균 80 토큰이 전달되고 80과 100 중 100만 통과. 다중 값은 IN 집합 포트로 연결 |

## 수용 기준 제안

- 자연어 의뢰에는 처리 목적·대상·성공 결과가 제시되며 시작부터 SQL 정답을 그대로 요구하지 않는다.
- SQL 용어를 모르는 첫 플레이어도 데이터 대상과 연산 변화의 관계를 관찰할 수 있다.
- 기본 설정으로 바로 정답이 되지 않는다. 학습자가 한 번 이상 데이터 의미에 근거한 판단을 한다.
- 화살표만 따라가거나 E를 반복하는 전략으로 모든 응용·도전 문제를 자동 해결할 수 없다.
- 매 문제 실행 전 예측과 실행 후 비교가 있고, 다음 문제 전 결과를 관찰할 시간이 있다.
- 오답은 '틀림'뿐 아니라 어떤 행·그룹·연결이 의뢰와 다른지 짚어준다.
- 정답과 같은 결과를 만드는 유효한 다른 질의도 문제의 학습 목표 범위에서 허용한다.
- 실제 결과 계산·NULL·중복·1:N 처리와 기존 배경·NPC·맵은 가능한 한 재사용한다.

## 이번 검토에서 하지 않은 일

게임 방식을 바꾸거나 실행 코드를 수정하지 않았다. 이 문서는 클로드 보완 작업에 전달할 검토 결과와 설계 기준이다. 초보자 대상 실제 플레이테스트, 전체 SQL 정확성 회귀 검사와 모든 해상도 검수는 별도다.
